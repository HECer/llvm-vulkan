What the project delivers

LLVM passes

Integer foldingBatched pure scalar operations through 64 bits.
Local CSEGPU hashing; exact equality and dominance stay on the host.
CFG cleanup and DCEGraph reachability with conservative roots and LLVM-owned IR edits.

Standalone compute API

Folding, reachability, dense dominators, gen/kill liveness, unsigned scan, key sorting and record hashing.

The standalone primitives do not replace LLVM’s register allocator, linker or native DominatorTree.

Optional accelerationSubgroup scans and shared-memory solvers run only when the device supports them.
Portable fallbacksGeneral shaders remain available when optional paths are disabled or unsupported.
Strict backend selectionAn explicit Vulkan request dispatches Vulkan or fails; it never reports a scalar fallback as GPU work.

Where the CPU still wins

151×

The CPU is faster on the tested long-chain mixed graph.

CPU: 0.0642 ms
GPU: 9.7100 ms

The CPU uses a work list. Vulkan still spends substantial work on convergence rounds.

CPU also wins every 1,024-element workload and scan at every measured size.

An improvement over earlier Vulkan does not imply a win over CPU. Work-efficient GPU frontiers and measured offload decisions remain future work.

The version 1.0 contract

Documented source APIC++17, defined integer and graph semantics, explicit errors and one compute instance per worker.
Relocatable distributionInstalled headers and static library, find_package support, benchmark CLI, embedded validated shaders and offline documentation.
Exact LLVM linkageBuild each plugin against the host LLVM installation. No cross-version LLVM binary ABI promise.
Performance by measurementCPU remains the conservative plugin default. No universal GPU offload or compiler-speedup guarantee.

Supported scope, platforms, compatibility and release gates

Remaining engineering work

Work-efficient GPU graph frontiersReduce redundant rounds before further tuning fixed-round kernels.
Measured offload decisionsUse representative compiler workloads; keep unprofitable work on CPU.
Broader compatibility and real buildsPhysical AMD/Intel devices, native Windows LLVM plugin ABI, more LLVM revisions and whole-compiler performance.

These are unimplemented follow-ups, not features or measured gains of version 1.0. Frontends, code generation, register allocation and linking remain upstream.
